# local 測試環境設定（WSL2，預設直跑 binary，可選 docker 模式）

> **Local-first 原則**：先用直跑 binary（最快、debug 方便），需要 container 行為才切 docker，**幾乎不用 fallback 到 home/cdrdla**。

## 連線資訊

| 項目          | 直跑 binary                  | local docker            |
| ------------- | ---------------------------- | ----------------------- |
| URL           | `http://localhost:8081`      | `http://localhost:8082` |
| Port          | `8081`                       | `8082`（避開 binary）   |
| 容器          | 無                           | `perch-local-test`      |
| Log           | `/tmp/perch.log`             | `docker logs perch-local-test` |

## 模式 1：直跑 binary（預設，最常用）

啟 binary **必須**先 source `tests/.env.local`，把完整 env 一次注入；不可只設 `LISTEN_ADDR/CLAUDE_WORKDIR/DB_PATH` 三個基本值，否則 Discord、GitLab 等可選 feature 不會啟動，相關測試會被誤判為「環境缺失」。

```bash
# 1. 編譯
cd /home/dorowu/workspace/mykb/code/perch
go build -o perch .

# 2. 確保 tests/.env.local 存在（gitignored，KEY=VAL 純文字；範本見下節）

# 3. Source env 後啟動
set -a; source tests/.env.local; set +a
./perch > /tmp/perch.log 2>&1 &

# 4. 確認
curl -s http://localhost:8081/ | head -5
tail -f /tmp/perch.log
```

### `tests/.env.local` 範本

該檔 gitignored，自行依需要新增註解或刪除可選區塊：

```bash
# --- 基本 ---
LISTEN_ADDR=:8081
CLAUDE_WORKDIR=/home/dorowu/workspace
DB_PATH=/tmp/perch.db
PERCH_MODE=single
AUTH_METHOD=none
# ADMIN_TOKEN=        # 不設定 → admin 路由全開放（本地方便）

# --- Discord（可選；要跑 Discord 測試時填入）---
# DISCORD_ACP_ENABLED=true
# DISCORD_BOT_TOKEN=<填入，從 .env.home.md 借同一把>
# DISCORD_CHANNEL_ID=1496644257149353994     # #myprivate2
# ACP_EXECUTABLE=claude-agent-acp
# ACP_RUN_TIMEOUT=120

# --- GitLab（可選；mock 模式自有腳本注入，這裡只在連真實 GitLab 才設）---
# AUTH_METHOD=gitlab
# PERCH_MODE=multi
# GITLAB_URL=...
# GITLAB_CLIENT_ID=...
# GITLAB_CLIENT_SECRET=...
# COOKIE_SECRET=$(openssl rand -hex 32)
```

### 環境變數對照

| 環境變數          | 本地預設值                      | 說明                                     |
| ----------------- | ------------------------------- | ---------------------------------------- |
| `LISTEN_ADDR`     | `:8081`                         | 避開 8080（可能被其他服務佔用）          |
| `CLAUDE_WORKDIR`  | `/home/dorowu/workspace`        | Claude Code 的工作目錄                   |
| `DB_PATH`         | `/tmp/perch.db`                 | SQLite，避免寫到 `/data`（本機沒有此路徑）|
| `PERCH_MODE`      | `single`（預設）                | 單使用者模式                             |
| `AUTH_METHOD`     | `none`（預設）                  | 本地開發不需要認證                        |
| `ADMIN_TOKEN`     | 不設定（預設）                  | 不設定則 admin 路由全開放                 |

> `ADMIN_TOKEN` 不設定時，Settings UI 和 `/admin/*` 路由對所有人開放，本地開發方便。

### 停止

```bash
lsof -ti tcp:8081 | xargs kill -9
# 或
pkill -f './perch'
```

## 模式 2：local docker（用於需要 container entrypoint / volume 行為的測試）

**何時用**：T26（entrypoint.sh 複製 skill）、T27（workspace volume 持久化），或任何需要驗證 container 啟動行為的 case。

### Compose 設定

`tests/docker-compose.local-test.yml` 已備好：

| 項目              | 值                                           |
| ----------------- | -------------------------------------------- |
| Image tag         | `perch:local-test`                           |
| 容器              | `perch-local-test`                           |
| Port              | `8082`（避開直跑 binary 的 8081）            |
| Workspace mount   | `tests/test-workspace` → `/workspace`        |
| /data mount       | `tests/test-data` → `/data`                  |
| ~/.claude mount   | `${HOME}/.claude:ro`（驗證 entrypoint 邏輯） |

### 啟動

```bash
cd /home/dorowu/workspace/mykb/code/perch

# 1. Build image（amd64，配合 Dockerfile）
docker buildx build --platform linux/amd64 -t perch:local-test .

# 2. 準備 .env.local-test（含測試用 token、Discord 等）
cat > tests/.env.local-test <<'EOF'
ADMIN_TOKEN=testtoken123
PERCH_MODE=single
AUTH_METHOD=none
PUID=1000
PGID=1000
EOF

# 3. 起容器
docker compose -f tests/docker-compose.local-test.yml --env-file tests/.env.local-test up -d

# 4. 確認
curl -s http://localhost:8082/ | head -5
docker logs perch-local-test --tail 30
```

### 停止／清理

```bash
docker compose -f tests/docker-compose.local-test.yml down
# 重置 workspace
rm -rf tests/test-workspace tests/test-data tests/test-perchuser
```

### ⚠️ Bot 衝突警告

**同一個 bot token 一次只能連一個 perch 進程**。在 local 跑 Discord 測試前，先停掉其他環境的 perch：

```bash
# 停掉 home 環境的 perch
ssh home-auto "/share/CACHEDEV4_DATA/.qpkg/container-station/bin/docker stop mykb-perch-test-perch-1"

# 停掉 cdrdla 環境的 perch
ssh admin@172.17.28.122 "/share/ZFS530_DATA/.qpkg/container-station/usr/bin/docker stop doppelganger-perch-1"
```

測試完別忘了把 home/cdrdla 啟回來。

### Discord 訊息驗證原則

| 方向 | 驗證方法 |
|------|---------|
| **bot → channel**（bot 主動發） | 用 Discord REST API：`curl -H "Authorization: Bot $DISCORD_BOT_TOKEN" "https://discord.com/api/v10/channels/$CHANNEL_ID/messages?limit=10"` 然後 grep 預期關鍵字 |
| **user → bot**（需要使用者傳訊） | 用 chrome-cdp 自動化（見 `test-discord-im.md` L12「傳訊自動化」），不需真人；只有 chrome-cdp 沒登入 Discord 才標 MANUAL |

## GitLab OAuth 設定（mock 模式，永久解 T50/T51/T53/RS08）

local 不連真實 GitLab，用 `tests/scripts/mock-gitlab-oauth.py` 模擬。

```bash
# 1. 啟動 mock OAuth server
python3 tests/scripts/mock-gitlab-oauth.py --port 18098 &

# 2. 啟動 perch（GitLab mode，指向 mock server）
LISTEN_ADDR=:18099 \
AUTH_METHOD=gitlab PERCH_MODE=multi \
GITLAB_URL=http://localhost:18098 \
GITLAB_CLIENT_ID=mock GITLAB_CLIENT_SECRET=mock \
GITLAB_REDIRECT_URI=http://localhost:18099/auth/callback \
COOKIE_SECRET=$(openssl rand -hex 32) \
DB_PATH=/tmp/perch-gitlab.db \
./perch &

# 3. 走 OAuth flow（dorowu）
curl -i "http://localhost:18099/auth/gitlab"
# → 302 到 mock /oauth/authorize → 302 回 callback → 設 perch_session cookie

# 4. 切換用戶（testuser2，用於多使用者隔離測試）
# /oauth/authorize?user=testuser2 會發 token-testuser2，回得到 id=999 的 user profile
```

兩個可用 mock user：

| 用戶 | id  | username  | access_token   |
|------|-----|-----------|----------------|
| dorowu     | 628 | dorowu    | token-dorowu    |
| testuser2  | 999 | testuser2 | token-testuser2 |

## 注意事項

| 項目               | 說明                                                                     |
| ------------------ | ------------------------------------------------------------------------ |
| `/data` 不存在     | 直跑 binary 模式必設 `DB_PATH=/tmp/perch.db`；docker 模式有 `/data` volume |
| frontend 需先 build | 若改了前端，先 `cd frontend && npm run build` 再重新編譯 Go binary       |
| port 8081/8082     | 8081 給直跑 binary，8082 給 local docker；要避免衝突可同時跑兩個         |

## Agent 操作規範

- **Local-first**：直跑 binary 為預設；只有 T26/T27 等需要 container 行為才切 docker 模式（同樣在 local，**不切 home/cdrdla**）
- 改了 Go 程式碼需 `go build`（binary 模式）或 `docker buildx build`（docker 模式）
- 改了前端需 `npm run build`（兩種模式都要）
- 測試截圖可存 `/tmp/`
